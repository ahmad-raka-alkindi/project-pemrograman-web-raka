A. Pendahuluan

Praktikum ini berfokus pada State Management dalam framework Flutter. State adalah data yang dapat berubah selama aplikasi berjalan dan memengaruhi tampilan (UI = f(state)). Pada praktikum ini dibangun aplikasi ResepKu yang memiliki fitur jumlah porsi (state lokal) dan fitur favorit yang dipakai bersama oleh beberapa halaman (state global). Konsep dan widget utama yang dipelajari meliputi:

a. StatefulWidget & setState()

State lokal (ephemeral) yang disimpan sebagai field pada class State dan hanya dibutuhkan oleh satu widget. Perubahan dibungkus setState() agar UI dibangun ulang.

b. ChangeNotifier & notifyListeners()

Class yang menyimpan app state sekaligus daftar listener. Pemanggilan notifyListeners() memberi tahu semua widget yang mendengarkan bahwa data telah berubah.

c. MultiProvider & ChangeNotifierProvider

Penyedia state yang dipasang di atas MaterialApp sehingga seluruh halaman (route) dapat mengakses state yang sama.

d. watch, read, dan Consumer

context.watch di build() untuk mendengarkan perubahan, context.read di callback untuk memanggil method, dan Consumer sebagai bentuk widget dari watch.

Aspek setState() Provider
Untuk state Lokal (ephemeral), dipakai satu widget App state, dipakai banyak widget dan halaman
Contoh di ResepKu Jumlah porsi di halaman detail Daftar resep favorit
Tempat data Field di class State Class yang meng-extend ChangeNotifier
Memberi tahu UI setState(() { ... }) notifyListeners()
Membaca data Langsung dari field context.watch<T>() di build(), context.read<T>() di callback

B. Tujuan

Setelah menyelesaikan praktikum ini, mahasiswa mampu:

  1. Membuat state lokal dengan StatefulWidget dan setState() pada fitur jumlah porsi di halaman detail.
  2. Menjelaskan keterbatasan state lokal ketika satu data dibutuhkan oleh banyak widget dan halaman.
  3. Membuat state global dengan package provider (ChangeNotifier dan MultiProvider) pada fitur favorit.
  4. Membaca state dengan context.watch, context.read, dan Consumer di beberapa halaman.

LANGKAH 2: EKSPERIMEN FAVORIT DENGAN STATE LOKAL

RecipeTile diubah menjadi StatefulWidget dengan field bool _isFavorite = false. Ikon hati pada setiap tile dibalik nilainya menggunakan setState(() => _isFavorite = !_isFavorite). Tujuan eksperimen ini adalah melihat langsung keterbatasan state lokal ketika data favorit dibutuhkan oleh banyak tempat (daftar resep, badge, halaman detail, dan halaman Favorit).

Jawaban Pengamatan (Langkah B.2)
  1. Apakah ikon hati berubah? Mengapa?
    Ya, ikon hati berubah dari favorite_border menjadi favorite berwarna merah. Penyebabnya, ketika ikon ditekan, setState() dipanggil di dalam _RecipeTileState sehingga nilai _isFavorite berubah dan Flutter membangun ulang (rebuild) tile tersebut.
  2. Dapatkah jumlah favorit ditampilkan di judul AppBar HomePage?
    Tidak dapat. Data _isFavorite berada di class _RecipeTileState, yaitu field private milik masing-masing tile. HomePage berada di atas tile pada widget tree dan tidak memiliki cara untuk membaca state milik widget anak, sehingga jumlah resep favorit tidak dapat dihitung.
  3. Bagaimana halaman detail mengetahui bahwa resep tersebut favorit?
    Tidak bisa. DetailPage hanya menerima objek recipe, sedangkan status favorit tersimpan di dalam state tile. Halaman detail adalah route baru yang tidak terhubung dengan state tile, sehingga status favorit tidak ikut terbawa dan tidak sinkron.
Kesimpulan Eksperimen:
Data favorit dibutuhkan di banyak tempat. Jika disimpan di dalam setiap tile, data tersebut tidak dapat dibaca oleh widget lain. Solusinya adalah memindahkan data ke atas, ke sebuah Provider.
LANGKAH 3: FITUR FAVORIT DENGAN PROVIDER

Daftar favorit disimpan sebagai app state, lalu dibaca dari daftar resep, halaman detail, badge, dan halaman Favorit. Tahapan pengerjaannya sebagai berikut:

  1. C.1 Memasang package dengan flutter pub add provider, lalu membuat FavoriteProvider extends ChangeNotifier berisi _items (private), getter items (unmodifiable), count, isFavorite(), toggle(), dan clear(). Resep dibandingkan berdasarkan id, bukan objeknya.
  2. C.2 Membungkus MaterialApp dengan MultiProvider di main() agar semua route dapat mengakses FavoriteProvider. Baris builder footer identitas tetap dipertahankan. Dilakukan hot restart karena hot reload tidak menjalankan ulang main().
  3. C.3 RecipeTile dikembalikan menjadi StatelessWidget. Status favorit dibaca dengan context.watch<FavoriteProvider>() di build(), dan tombol memanggil context.read<FavoriteProvider>().toggle(recipe) di callback.
  4. C.4 Menambahkan tombol hati pada actions AppBar di DetailPage. Halaman ini kini memakai dua jenis state sekaligus: _servings (lokal, setState) dan favorit (global, Provider).
  5. C.5 Membuat FavoritePage dengan Consumer<FavoriteProvider> yang menampilkan pesan kosong atau daftar favorit beserta tombol hapus per item.
  6. C.6 Membuat widget FavoriteBadgeButton menggunakan Badge Material 3 dan memasangnya di AppBar HomePage agar hanya bagian badge yang rebuild saat jumlah favorit berubah.

LANGKAH 5: PERTANYAAN ANALISIS
1. Jawaban tiga pertanyaan pada Langkah B.2

Ikon hati berubah karena setState() pada _RecipeTileState membangun ulang tile yang bersangkutan. Jumlah favorit tidak dapat ditampilkan di AppBar HomePage karena _isFavorite adalah field private di dalam state masing-masing tile, sedangkan HomePage tidak dapat membaca state milik widget anaknya. Halaman detail juga tidak dapat mengetahui status favorit karena hanya menerima objek recipe dan tidak terhubung dengan state tile. Dengan kata lain, state lokal hanya dapat dibaca oleh widget pemiliknya sendiri.

2. Mengapa jumlah porsi tetap memakai setState() dan tidak dimasukkan ke Provider?

Jumlah porsi hanya dibutuhkan oleh satu halaman, yaitu halaman detail, sehingga termasuk state lokal (ephemeral) dan tidak perlu dibagikan ke widget lain. Hal ini terbukti pada skenario 6 Langkah C.7: setelah porsi diubah menjadi 2 lalu halaman ditutup, porsi kembali ke nilai awal saat resep dibuka lagi karena state lokal ikut dibuang bersama halamannya. Perilaku ini memang sesuai kebutuhan. Seandainya porsi disimpan di Provider, nilainya akan bertahan dan terbawa ke pembukaan berikutnya (bahkan bercampur antar resep), serta memaksa widget lain ikut mendengarkan data yang tidak mereka perlukan.

3. Memindahkan ChangeNotifierProvider dari main() ke dalam HomePage

Ketika ChangeNotifierProvider dipindahkan ke dalam HomePage (membungkus Scaffold) lalu halaman Favorit dibuka, aplikasi menampilkan layar error ProviderNotFoundException. Penyebabnya adalah posisi provider di widget tree. FavoritePage dibuka melalui Navigator.push, sehingga menjadi route baru yang berada di bawah Navigator milik MaterialApp, sejajar dengan HomePage dan bukan keturunannya. Provider hanya dapat ditemukan oleh widget yang berada di bawahnya pada widget tree, jadi context milik FavoritePage tidak menemukan FavoriteProvider. Karena itu provider harus dipasang di atas MaterialApp agar semua route dapat mengaksesnya. Setelah percobaan, kode dikembalikan seperti semula.

import 'package:flutter/foundation.dart';
import 'package:resepku/models/recipe.dart';

class FavoriteProvider extends ChangeNotifier {
  final List<Recipe> _items = [];

  // Dari luar hanya boleh dibaca, tidak boleh diubah langsung
  List<Recipe> get items => List.unmodifiable(_items);

  int get count => _items.length;

  bool isFavorite(Recipe recipe) => _items.any((r) => r.id == recipe.id);

  void toggle(Recipe recipe) {
    if (isFavorite(recipe)) {
      _items.removeWhere((r) => r.id == recipe.id);
    } else {
      _items.add(recipe);
    }
    notifyListeners(); // beri tahu semua widget yang "mendengarkan"
  }

  void clear() {
    _items.clear();
    notifyListeners();
  }
}

import 'package:flutter/material.dart';

class ThemeProvider extends ChangeNotifier {
  ThemeMode _themeMode = ThemeMode.light;

  ThemeMode get themeMode => _themeMode;

  bool get isDark => _themeMode == ThemeMode.dark;

  void setDark(bool value) {
    _themeMode = value ? ThemeMode.dark : ThemeMode.light;
    notifyListeners();
  }
}

class RecipeTile extends StatelessWidget {
  const RecipeTile({super.key, required this.recipe});

  final Recipe recipe;

  @override
  Widget build(BuildContext context) {
    // watch: widget ini ikut rebuild saat daftar favorit berubah
    final isFavorite = context.watch<FavoriteProvider>().isFavorite(recipe);

    return ListTile(
      leading: CircleAvatar(child: Text(recipe.name[0])),
      title: Text(recipe.name),
      subtitle: Text(
        '${recipe.cuisine} • ${recipe.totalTimeMinutes} menit • ★ ${recipe.rating}',
      ),
      trailing: IconButton(
        icon: Icon(
          isFavorite ? Icons.favorite : Icons.favorite_border,
          color: isFavorite ? Colors.red : null,
        ),
        // read: di dalam callback cukup "membaca", tidak perlu listen
        onPressed: () => context.read<FavoriteProvider>().toggle(recipe),
      ),
      onTap: () => Navigator.push(
        context,
        MaterialPageRoute(builder: (context) => DetailPage(recipe: recipe)),
      ),
    );
  }
}

import 'package:flutter/material.dart';
import 'package:provider/provider.dart';
import 'package:resepku/models/recipe.dart';
import 'package:resepku/providers/favorite_provider.dart';

class DetailPage extends StatefulWidget {
  const DetailPage({super.key, required this.recipe});

  final Recipe recipe;

  @override
  State<DetailPage> createState() => _DetailPageState();
}

class _DetailPageState extends State<DetailPage> {
  late int _servings; // state lokal: hanya halaman ini yang butuh

  @override
  void initState() {
    super.initState();
    _servings = widget.recipe.servings; // nilai awal dari data resep
  }

  void _addServing() {
    setState(() => _servings++);
  }

  void _removeServing() {
    if (_servings > 1) {
      setState(() => _servings--);
    }
  }

  @override
  Widget build(BuildContext context) {
    final recipe = widget.recipe;
    final totalCalories = recipe.caloriesPerServing * _servings;
    final isFavorite = context.watch<FavoriteProvider>().isFavorite(recipe);
    final textTheme = Theme.of(context).textTheme;

    return Scaffold(
      appBar: AppBar(
        title: Text(recipe.name),
        actions: [
          IconButton(
            icon: Icon(isFavorite ? Icons.favorite : Icons.favorite_border),
            onPressed: () => context.read<FavoriteProvider>().toggle(recipe),
          ),
        ],
      ),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          Text(
            '${recipe.cuisine} • ${recipe.difficulty} • ${recipe.totalTimeMinutes} menit',
            style: textTheme.bodyLarge,
          ),
          const SizedBox(height: 16),
          Card(
            child: Padding(
              padding: const EdgeInsets.all(12),
              child: Row(
                children: [
                  Text('Porsi', style: textTheme.titleMedium),
                  const Spacer(),
                  IconButton.filledTonal(
                    onPressed: _servings > 1 ? _removeServing : null,
                    icon: const Icon(Icons.remove),
                  ),
                  Padding(
                    padding: const EdgeInsets.symmetric(horizontal: 16),
                    child: Text('$_servings', style: textTheme.titleLarge),
                  ),
                  IconButton.filledTonal(
                    onPressed: _addServing,
                    icon: const Icon(Icons.add),
                  ),
                ],
              ),
            ),
          ),
          const SizedBox(height: 8),
          Text('Total kalori: $totalCalories kkal', style: textTheme.titleMedium),
          const SizedBox(height: 24),
          Text('Bahan', style: textTheme.titleLarge),
          for (final item in recipe.ingredients)
            ListTile(
              dense: true,
              leading: const Icon(Icons.check_circle_outline),
              title: Text(item),
            ),
        ],
      ),
    );
  }
}

import 'package:flutter/material.dart';
import 'package:provider/provider.dart';
import 'package:resepku/providers/favorite_provider.dart';

class FavoritePage extends StatelessWidget {
  const FavoritePage({super.key});

  Future<void> _confirmClear(BuildContext context) async {
    final ok = await showDialog<bool>(
      context: context,
      builder: (dialogContext) => AlertDialog(
        title: const Text('Hapus semua favorit?'),
        content: const Text('Seluruh resep favorit akan dihapus dari daftar.'),
        actions: [
          TextButton(
            onPressed: () => Navigator.pop(dialogContext, false),
            child: const Text('Batal'),
          ),
          FilledButton(
            onPressed: () => Navigator.pop(dialogContext, true),
            child: const Text('Hapus'),
          ),
        ],
      ),
    );
    if (ok == true && context.mounted) {
      context.read<FavoriteProvider>().clear();
    }
  }

  @override
  Widget build(BuildContext context) {
    final isEmpty = context.watch<FavoriteProvider>().count == 0;

    return Scaffold(
      appBar: AppBar(
        title: const Text('Favorit Saya'),
        actions: [
          TextButton.icon(
            // null = tombol nonaktif ketika daftar favorit kosong
            onPressed: isEmpty ? null : () => _confirmClear(context),
            icon: const Icon(Icons.delete_sweep),
            label: const Text('Hapus semua'),
          ),
        ],
      ),
      body: Consumer<FavoriteProvider>(
        builder: (context, favorite, child) {
          if (favorite.count == 0) {
            return const Center(
              child: Text(
                'Belum ada resep favorit.\nTekan ikon hati di daftar resep.',
                textAlign: TextAlign.center,
              ),
            );
          }
          return ListView(
            children: [
              for (final recipe in favorite.items)
                ListTile(
                  title: Text(recipe.name),
                  subtitle: Text(recipe.cuisine),
                  trailing: IconButton(
                    icon: const Icon(Icons.delete_outline),
                    onPressed: () => favorite.toggle(recipe),
                  ),
                ),
            ],
          );
        },
      ),
    );
  }
}

    final theme = context.watch<ThemeProvider>();

    return Scaffold(
      appBar: AppBar(title: const Text('Pengaturan')),
      body: ListView(
        children: [
          SwitchListTile(
            title: const Text('Mode gelap'),
            secondary: const Icon(Icons.dark_mode),
            value: theme.isDark,
            onChanged: (value) => context.read<ThemeProvider>().setDark(value),
          ),
        ],
      ),
    );
  }
}

File lib/data/dummy_recipes.dart berisi enam data resep dummy (sama dengan enam resep pertama pada dummyjson.com/recipes) dan dapat dilihat lengkap pada repository GitHub.

D. Kesimpulan

Kesimpulan dari praktikum ini adalah saya telah memahami perbedaan state lokal dan state global pada Flutter. setState() cocok untuk data yang hanya dibutuhkan satu widget, seperti jumlah porsi pada halaman detail, sedangkan data yang dibagikan ke banyak widget dan halaman, seperti daftar favorit, sebaiknya disimpan pada ChangeNotifier dan disediakan melalui Provider di atas MaterialApp. Penggunaan context.watch di build(), context.read di callback, dan Consumer membuat UI selalu sinkron dengan data setelah notifyListeners() dipanggil. Aplikasi ResepKu berhasil mengimplementasikan fitur porsi, favorit, badge, halaman Favorit, tema gelap dan terang, serta fitur hapus semua favorit dengan konfirmasi.
